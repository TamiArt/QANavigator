# Принципы создания учебных инфографик QA Navigator

## 1. Инфографика = учебный материал, а не декоративная карточка

Каждая инфографика должна помогать изучить тему без возвращения к длинному тексту урока.

Базовая цепочка:

**исходный материал → сжатые факты → визуальная связь → запоминающий образ**

Если важный факт урока не представлен ни текстом, ни схемой, ни визуальной метафорой, инфографика считается неполной.

---

## 2. Урок 4 из 12 — Scrum — visual master template серии

Утверждённая пользователем инфографика **«Урок 4 из 12 — Scrum»** является главным визуальным образцом для всей серии учебных инфографик Learning Mode.

Это означает: следующие инфографики должны строиться **по той же системе**, а не просто иметь похожую цветовую палитру.

### Что обязательно сохраняем от Scrum-образца

- вертикальный poster-формат;
- единый светлый фон;
- компактный верхний заголовочный блок;
- понятную визуальную иерархию: тема → ключевая мысль → смысловые секции → итоговая memory cue;
- крупные округлённые карточки;
- цветные номера секций;
- тёмно-синие заголовки;
- мягкую пастельную палитру;
- flat-vector иллюстрации;
- небольшие тематические пиктограммы внутри карточек;
- плотную, но не перегруженную A4-подобную подачу;
- равномерный ритм карточек и отступов;
- отдельный нижний блок с короткой формулой/выводом для запоминания;
- единый масштаб и визуальный вес элементов;
- отсутствие декоративных элементов, которые не помогают понять тему.

### Главное

**Scrum задаёт визуальную систему, а не содержание.**

Нельзя механически копировать расположение текста, количество карточек или конкретные иконки, если они не подходят новой теме. Сохраняется логика композиции и визуальный язык, а смысловая структура адаптируется под исходный урок.

---

## 3. Сначала содержание, затем визуальная композиция

Перед созданием инфографики необходимо:

1. прочитать полный источник урока;
2. выделить обязательные факты, определения, связи и последовательности;
3. сжать их без потери смысла;
4. определить визуальную связь между фактами;
5. только после этого проектировать карточки и иллюстрации.

Рабочая формула:

**источник → факты → смысловые группы → визуальная структура → memory cue**

Нельзя начинать с красивых карточек и затем пытаться «вставить» в них содержание.

Если исходный урок не содержит достаточно информации, запрещено додумывать материал ради заполнения инфографики.

---

## 4. Структура каждой инфографики должна быть похожа на Scrum-образец

Каждая новая инфографика должна по возможности иметь следующие уровни:

### 4.1. Заголовок темы

У каждой темы должен быть **свой заголовок**, соответствующий конкретному уроку.

Запрещены универсальные заголовки вроде:

- «Ключевая схема»;
- «Основные моменты»;
- «Погружение в контекст»,

если они не являются названием самого урока.

### 4.2. Короткая главная мысль

Под заголовком или рядом с ним должна быть одна короткая фраза, которая отвечает на вопрос:

**«Что нужно запомнить об этой теме в первую очередь?»**

Она должна быть понятна без чтения всего урока.

### 4.3. Смысловые секции

Материал разбивается на несколько крупных карточек.

Количество карточек **не фиксировано**. Оно определяется содержанием урока.

Карточка должна отвечать на один смысловой вопрос, например:

- что это;
- зачем нужно;
- из чего состоит;
- как работает;
- чем отличается;
- какие этапы;
- какие плюсы/минусы;
- что важно запомнить.

### 4.4. Итоговая memory cue

В нижней части по образцу Scrum желательно размещать короткую формулу, цепочку или правило для быстрого повторения.

Формула всегда должна быть основана на реальном содержании конкретного урока.

---

## 5. Визуальная функция каждой секции

Каждый блок должен не просто содержать текст, а показывать отношение между фактами.

Используются подходящие типы:

- **flow** — последовательность;
- **timeline** — этапы во времени;
- **compare** — сравнение;
- **layers** — уровни;
- **cycle** — цикл;
- **network** — взаимосвязи;
- **checklist** — список проверки;
- **pyramid** — иерархия;
- **roles/map** — роли и связи между участниками;
- **artifacts** — сущности/артефакты и их назначение.

Если материал описывает процесс, предпочтителен flow/timeline/cycle, а не набор независимых иконок.

Если материал сравнивает понятия, предпочтителен compare.

Если материал описывает взаимосвязи, предпочтителен network.

---

## 6. Семантические иллюстрации

Иллюстрация должна помогать понять или запомнить содержание.

Примеры:

- цель → target;
- команда → люди;
- процесс → gear;
- документация → document;
- коммуникация → chat;
- код → code;
- поиск информации → search;
- результат проверки → checklist;
- продуктовая ценность → star;
- понимание → brain/lightbulb;
- время/спринт → calendar/timeline.

Нельзя использовать одну универсальную иконку только потому, что она визуально подходит.

**Сначала смысл → потом иллюстрация.**

---

## 7. Визуальный язык Scrum-образца

Все новые инфографики должны восприниматься как страницы одного учебника.

Обязательная стилистика:

- flat vector;
- очень светлый/белый фон;
- пастельные голубые, лавандовые, мятные, жёлтые, розовые и оранжевые акценты;
- тёмно-синие заголовки и контуры;
- округлённые карточки;
- мягкие, ненавязчивые тени;
- дружелюбные hand-drawn/vector элементы;
- простые формы;
- минимум мелких деталей;
- отсутствие 3D;
- отсутствие glassmorphism;
- отсутствие тяжёлых реалистичных фотографий;
- отсутствие тёмного фона.

Цвет используется для **иерархии и группировки**, а не как украшение.

---

## 8. Сетка, пропорции и ритм

Композиция должна следовать Scrum-образцу:

- единый вертикальный poster;
- стабильные внешние поля;
- равномерные промежутки между секциями;
- одинаковая логика внутренних отступов;
- визуально сбалансированные карточки;
- номера секций имеют единый размер и положение;
- заголовок карточки отделён от основного текста;
- иллюстрация не разрушает сетку;
- нижняя memory cue визуально отделена от основного контента.

Для poster-style SVG предпочтительно использовать единый viewBox 1065 × 1476 и масштабирование без изменения пропорций.

Если содержанию требуется другая высота, разрешается изменить высоту poster, но нельзя ломать саму систему сетки и соотношение элементов.

---

## 9. Текст всегда находится внутри предназначенного ему блока

Это обязательное правило Scrum-образца.

Нельзя допускать:

- выхода текста за границы карточки;
- обрезания;
- наложения строк;
- текста поверх иллюстрации;
- слишком маленьких внутренних отступов;
- последней строки вплотную к границе;
- случайного переноса;
- пересечения текста с соседним блоком.

Каждый текстовый блок должен иметь **реальную зарезервированную область**.

Перед финализацией проверяется:

1. заголовок полностью помещается;
2. основной текст полностью помещается;
3. строки не накладываются;
4. между строками есть комфортный интервал;
5. внутренние отступы сохранены;
6. последняя строка не касается нижней границы;
7. иллюстрация не уменьшает критически читаемую область.

---

## 10. Переносы делаются по смыслу

Нужно использовать логические строки.

Хорошо:

> Анализ кода и
> репозитория

Плохо:

> Анализ кода и репозит-
> ория

Для длинных пояснений лучше использовать 2–3 короткие смысловые строки.

Заголовок может занимать две строки, если это улучшает композицию.

---

## 11. Не уменьшать шрифт ради того, чтобы всё влезло

Если текст не помещается, исправление выполняется в таком порядке:

1. убрать лишнее декоративное пространство;
2. уменьшить иллюстрацию;
3. изменить положение иллюстрации;
4. переразбить текст на смысловые строки;
5. увеличить полезную область карточки;
6. изменить размеры соседних элементов;
7. только затем немного уменьшить шрифт.

Нельзя решать проблему переполнения микроскопическим текстом.

**Читаемость важнее плотности.**

---

## 12. Баланс текста и изображения

В каждой карточке сначала резервируется место для текста.

После этого определяется размер иллюстрации.

Правила:

- текст важнее декоративной картинки;
- иллюстрация не должна конкурировать с заголовком;
- в маленькой карточке — компактная иллюстрация;
- в крупном смысловом блоке — более заметная схема;
- свободное место не является причиной увеличивать изображение;
- иллюстрация должна усиливать смысл, а не просто заполнять пустоту.

---

## 13. Инфографика должна быть визуально насыщенной, но не перегруженной

Scrum-образец задаёт правильный баланс:

**много полезной информации + короткие фрагменты текста + понятные визуальные связи + свободное пространство.**

Не превращать инфографику в:

- сплошную стену текста;
- набор маленьких карточек;
- каталог случайных иконок;
- декоративный постер без учебной ценности.

Каждая карточка должна иметь одну понятную функцию.

---

## 14. Адаптивность обязательна

Инфографика должна корректно работать:

- на desktop;
- на планшете;
- на мобильном экране;
- в PDF.

Для poster-style SVG:

- сохранять исходные пропорции;
- масштабировать по ширине;
- не допускать горизонтального overflow;
- не растягивать иконки;
- не обрезать элементы;
- не скрывать важный текст;
- сохранять читаемость.

В интерфейсе Learning Mode poster должен помещаться в доступную ширину контейнера.

---

## 15. PDF должен сохранять ту же композицию

После сохранения в PDF должно оставаться то же визуальное произведение, которое пользователь видит в Learning Mode.

Проверять:

- poster полностью попадает в PDF;
- ничего не обрезается;
- текст остаётся читаемым;
- пропорции сохраняются;
- иллюстрации не растягиваются;
- карточки сохраняют иерархию;
- memory cue остаётся на своём месте.

---

## 16. Не копировать содержание Scrum в другие уроки

Scrum — **visual master template**, но не контентный шаблон.

Для нового урока запрещено автоматически переносить:

- роли Product Owner / Scrum Master / Developers;
- Sprint;
- Backlog;
- Increment;
- Scrum-события;
- Scrum-термины;
- Scrum-иконки,

если их нет в исходном материале нового урока.

Переносятся только:

**визуальная система + композиционный принцип + типографика + сетка + качество подачи.**

---

## 17. Контроль качества перед коммитом

Перед завершением каждой инфографики выполняется обязательный аудит.

### Content

- Все важные факты исходного урока представлены.
- Нет выдуманных фактов.
- Термины сохранены корректно.
- Содержание соответствует конкретному уроку.
- Ничего существенного не потеряно при сжатии.

### Structure

- Есть собственный заголовок темы.
- Есть короткая главная мысль.
- Смысловые блоки логично организованы.
- Визуальная структура соответствует типу материала.
- Есть memory cue, если она помогает теме.

### Layout

- Все блоки помещаются.
- Нет пересечений.
- Нет переполнения.
- Отступы равномерны.
- Карточки визуально сбалансированы.
- Иллюстрации соразмерны.

### Typography

- Заголовки читаются.
- Основной текст не слишком мелкий.
- Строки не накладываются.
- Переносы сделаны по смыслу.
- Текст не выходит за границы блока.

### Visual

- Каждая иллюстрация связана с содержанием.
- Нет случайных декоративных элементов.
- Все страницы выглядят частью одного учебного набора.
- Стилистика соответствует Scrum visual master template.

### Responsive

- Desktop проверен.
- Mobile проверен.
- SVG не растягивается.
- Нет горизонтального overflow.
- Важные элементы не обрезаются.

### PDF

- Poster полностью сохраняется.
- Нет обрезанных частей.
- Читаемость сохраняется.
- Пропорции не меняются.

---

## 18. Главное правило серии

**Сначала смысл и читаемость → затем структура → затем композиция → затем семантические иллюстрации → затем декоративные детали.**

Урок 4 из 12 — Scrum задаёт стандарт того, **как должна выглядеть и ощущаться вся серия**.

Инфографика должна быть не просто красивой, а такой, чтобы QA-инженер мог:

**увидеть → понять → связать → запомнить → быстро повторить материал.**
