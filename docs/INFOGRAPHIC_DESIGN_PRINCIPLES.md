# Принципы создания учебных инфографик QA Navigator

## 1. Инфографика = учебный материал, а не декоративная карточка

Каждая инфографика должна помогать изучить тему без возвращения к длинному тексту урока.

Базовая цепочка:

**исходный материал → сжатые факты → визуальная связь → запоминающий образ**

Если важный факт урока не представлен ни текстом, ни схемой, ни визуальной метафорой, инфографика считается неполной.

---

## 2. Референс задаёт визуальный стандарт

Если для темы утверждён референс, его нужно воспринимать как **образец композиции**, а не как общее настроение.

Сохраняем:
- пропорции и общую геометрию;
- расположение крупных блоков;
- визуальную иерархию;
- количество и характер секций;
- систему нумерации;
- стиль карточек;
- пастельную палитру;
- характер иллюстраций;
- плотность информации;
- баланс текста и изображений;
- общий ритм отступов.

Меняется только то, что относится к конкретной теме: заголовки, факты, схемы и тематические иллюстрации.

---

## 3. Все элементы должны быть соразмерны

Иконка или иллюстрация не должна конкурировать с содержанием.

Правила:
- сначала резервируем пространство под текст;
- затем подбираем размер иллюстрации;
- не увеличиваем картинку только ради заполнения свободного места;
- иллюстрация должна поддерживать смысл блока;
- в маленьких карточках иллюстрации компактные;
- крупные изображения используются только в крупных смысловых блоках.

**Текст важнее декоративной картинки.**

---

## 4. Текст всегда должен помещаться в свой блок

Нельзя допускать:
- обрезания текста;
- выхода текста за границы карточки;
- наложения строк;
- слишком тесного расстояния между строками;
- текста поверх иллюстрации;
- последней строки вплотную к нижней границе;
- переноса, который разрушает смысл заголовка.

Перед финализацией каждого блока проверяем:

1. Заголовок полностью помещается.
2. Все строки основного текста помещаются.
3. Между строками есть читаемый интервал.
4. Между текстом и границей карточки есть внутренний отступ.
5. Иллюстрация не уменьшает читаемую область текста.
6. Последняя строка не касается нижней границы.

---

## 5. Не уменьшать шрифт для решения проблемы переполнения

Если текст не помещается, порядок исправления такой:

1. убрать лишнее декоративное пространство;
2. уменьшить иллюстрацию;
3. изменить положение иллюстрации;
4. переразбить текст на логические строки;
5. увеличить внутреннее пространство блока;
6. изменить размеры соседних элементов;
7. только после этого немного уменьшить шрифт.

Нельзя превращать инфографику в «мелкий шрифт ради того, чтобы всё влезло».

Основной текст должен оставаться комфортным для чтения.

---

## 6. Использовать визуальные переносы, а не случайные переносы

Строки должны переноситься по смыслу.

Хорошо:

> Анализ кода и  
> репозитория

Плохо:

> Анализ кода и репозит-  
> ория

Для заголовков допускается 2 строки, если это улучшает композицию.

Для длинных пояснений лучше использовать 2–3 короткие смысловые строки, чем одну перегруженную строку.

---

## 7. Каждая секция должна иметь собственную визуальную функцию

Возможные типы:

- **flow** — последовательность;
- **timeline** — этапы во времени;
- **compare** — сравнение;
- **layers** — уровни;
- **cycle** — цикл;
- **network** — взаимосвязи;
- **checklist** — список проверки;
- **pyramid** — иерархия.

Нельзя использовать одну и ту же декоративную иконку для всех смыслов.

---

## 8. Иллюстрации должны быть семантическими

Иллюстрация должна помогать понять тему.

Примеры:
- цель → target;
- команда → люди;
- процесс → gear;
- документация → document;
- коммуникация → chat;
- код → code;
- поиск информации → search;
- результат проверки → checklist;
- продуктовая ценность → star;
- понимание → brain/lightbulb.

Не использовать случайные красивые изображения, если они ничего не добавляют к пониманию темы.

---

## 9. Иллюстрации должны быть в одном визуальном языке

Для утверждённого стиля используем:

- flat vector;
- мягкие пастельные цвета;
- тёмно-синие контуры;
- округлённые формы;
- лёгкие тени;
- минимальное количество мелких деталей;
- белые или очень светлые поверхности;
- отсутствие 3D/glassmorphism;
- отсутствие тяжёлых реалистичных фотографий.

Все новые иллюстрации должны выглядеть как часть одного учебного набора.

---

## 10. Адаптивность обязательна

Инфографика должна корректно работать:

- на desktop;
- на планшете;
- на мобильном экране;
- в PDF.

Для poster-style SVG предпочтительно использовать единый `viewBox` и масштабирование по ширине.

Не допускается:
- горизонтальный скролл;
- обрезанные элементы;
- изменение пропорций изображения;
- растяжение иконок;
- исчезновение важных элементов;
- слишком маленький текст на мобильном.

---

## 11. PDF должен сохранять ту же композицию

То, что хорошо выглядит в браузере, должно хорошо выглядеть и после сохранения.

Перед завершением проверяем:
- весь poster попадает в PDF;
- ничего не обрезается;
- текст остаётся читаемым;
- пропорции не меняются;
- иллюстрации не растягиваются;
- блоки сохраняют исходную иерархию.

---

## 12. Один утверждённый референс может стать шаблоном серии

Если пользователь утверждает конкретную инфографику как образец, она становится **visual master template** для следующих тем.

Для серии сохраняются:
- сетка;
- размеры и пропорции крупных секций;
- стиль нумерации;
- типографическая иерархия;
- палитра;
- отступы;
- стиль иллюстраций;
- плотность информации;
- принцип размещения текста и изображения.

Для каждой новой темы меняются:
- содержание;
- количество смысловых карточек при необходимости;
- тематические схемы;
- тематические иллюстрации.

Не копируем содержание одной темы в другую.

---

## 13. Контроль качества перед коммитом

Перед завершением каждой инфографики выполняется визуальный аудит:

### Content
- Все важные факты исходного урока представлены.
- Нет выдуманных фактов.
- Термины сохранены корректно.
- Информация соответствует теме.

### Layout
- Все блоки помещаются.
- Нет пересечений.
- Нет переполнения.
- Отступы визуально равномерны.
- Картинки соразмерны.

### Typography
- Заголовки читаются.
- Основной текст не слишком мелкий.
- Строки не накладываются.
- Переносы сделаны по смыслу.

### Visual
- Каждая иллюстрация связана с содержанием.
- Нет случайных декоративных иконок.
- Все элементы выдержаны в едином стиле.

### Responsive
- Desktop проверен.
- Mobile проверен.
- SVG не растягивается.
- Нет горизонтального overflow.

### PDF
- Poster полностью сохраняется.
- Нет обрезанных частей.
- Читаемость сохраняется.

---

## 14. Главное правило серии

**Сначала читаемость и смысл → затем композиция → затем иллюстрации → затем декоративные детали.**

Инфографика должна выглядеть красиво, но её главная задача — позволить QA-инженеру быстро понять, связать и запомнить материал.
