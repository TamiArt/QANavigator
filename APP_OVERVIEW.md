# QA Navigator — архитектура и логика

QA Navigator — offline-first React/Vite приложение для практической работы тестировщика. Основные локальные сценарии не требуют сети и API-ключей.

## Функции
1. **Рабочее пространство** — проектный контекст.
2. **Мастер для новичка** — детерминированный rule-based план проверок.
3. **Анализ требований** — локальная работа с требованиями и опциональный AI-анализ.
4. **Тест-дизайн** — Pairwise/IPOG, классы эквивалентности, BVA, таблицы решений, переходы состояний.
5. **Выполнение тестов** — статусы чек-листов, результаты и баг-репорты.
6. **Автотесты** — генерация примеров кода по выбранному стеку через опциональный AI.
7. **Релизный отчёт** — локальные метрики и опциональная AI-сводка.
8. **Генератор данных** — готовые наборы boundary/special/XSS/email/date данных.
9. **База знаний QA** — справочник, поиск, фильтры и закладки.
10. **Документация** — чек-листы, тест-кейсы, тест-планы, баг-репорты, отчёты и RTM.
11. **Настройки** — AI-провайдеры, backup/import/export и очистка локальных данных.

## Архитектурные правила
- `src/app/domain` — общие доменные типы.
- `src/app/core` — контекст приложения, конфигурация и внешние AI-вызовы.
- `src/app/components` — действительно общие UI-компоненты.
- `src/app/features/<feature>` — изолированная бизнес-функция.
- `src/app/handbook-*` — контент базы знаний, отделённый от UI.
- `src/app/hooks` — React hooks общего назначения.
- `src/app/lib` — маленькие технические адаптеры.

`App.tsx` отвечает только за композицию приложения, навигацию, глобальное состояние и layout. Бизнес-логика модулей не должна возвращаться в него.

## Поток данных
`localStorage → hook → AppContext → feature`

AI работает только по явному действию пользователя:
`feature → core/ai → выбранный provider → результат → feature state`

Локальные алгоритмы тест-дизайна не должны зависеть от AI.

## Данные
Существующие ключи localStorage сохраняются для обратной совместимости:
- `qa_nav_theme`
- `qa_nav_apikeys`
- `qa_navigator_checklists`
- `qa_navigator_testcases`
- `qa_navigator_bugreports`
- `qa_navigator_bookmarks`
- `qa_navigator_req_text`
- `qa_navigator_req_result`

При изменении структуры сохранённых данных следующей реализацией должна быть добавлена версия схемы и миграция; существующие данные нельзя silently overwrite.

## AI
AI не является обязательной частью приложения. Ключи вводятся пользователем и остаются в browser storage текущего режима. Запросы уходят только выбранному провайдеру. Бесплатность внешнего провайдера не считается гарантированной.

## Правила разработки
- `main` не изменять напрямую; рабочие изменения выполняются в feature/refactor ветках и попадают в `main` только через PR.
- Новый модуль должен иметь одну ответственность.
- Жёсткий максимум исходного `.ts/.tsx` файла: **1500 строк**.
- Не создавать `Old`, `Legacy`, `V2`, `Copy` параллельные реализации.
- Новая функциональность сначала добавляется в этот файл, чтобы архитектурная карта не устаревала.
- Перед PR обязательно выполнять `npm run verify`.
